*Instead one service emit event and other service react to that event
*Event is something that happned in past
*and that cant be changed
*and that its has all info about it like order created is an event

*Here there are lot of disadvantages here 
*Problems with the synchronous communications is 
1.Here first of all to complete the place order flow all the services must be available
*even if one service down than also flow cant be completed

2.Total letnecy is the sum of the latency of all the microservices
3.Cascading failure is actually if one service is slow it will cascade or flow to other microservices
4.Then there is very tight coupling
5.We can scale only one microservice on the basis of load

Key compoennets of the event driven architecture are 
1.Prducer is the service which publish the event
2.Router who push the events
3.Consumer who consumes the event or service who react to the event


Eda models
:
1.Pub/sub
*Events are published to active consumers and then they are forgotten
*Suppose new consumers comes it will not get the yesterday messages
Mostly used when we care about the delivery 
not the past history


2.SWtreaming
Events are appended in logs forever and can be retained
If new consumer comes than it can baiscally read from latest offset or from day 1 if retention is allowed
example:kafka
