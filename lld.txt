Food delivery applications
*Here we have the 3 intermediator first is the user than hotel ownere and then delivery partner
*Functional Requirements

User should be able to register into our application

List down all the nearby restaurants based on user location

User should able to search restaurants based on title and name

User shall be able to add any of the restaurant items

User should able to select restaurants, add items to the cart and make the payment to confirm the order

Once the restaurant accept, find nearby delivery partner based on user location, optimized delivery time

Once the delivery partner picks up the order, give almost real time location of delivery partner to user

User should get notification at all stages and get past orders in the profile

Non-Functional Requirements

Scale: 5M users and 1M restaurants

CAP Theorem: Application should be highly available based on searching. And our application should be highly consistent based on payments and order of food from restaurant

Distributed job scheduler
*1. Functional Requirements

User can create/schedule a job (immediate/future/cron)

Monitor the status of job (real time)

Support update/cancel scheduled jobs

Out of Scope: dependence in job (DAG)

2.Non Functional Requirements

Scale: 1M jobs/sec

CAP Theorem: Availability > Consistency

Job should run at least once

Latency: The system should execute the jobs within 2s of their scheduled time
